「帰りに牛乳を買ってきて」

家族にそう頼めば、たいていは通じます。牛乳が売っている店を探し、棚から商品を取り、会計を済ませる。頼まれた人は、言われなかった手順まで考えて動いてくれます。

では、同じことをコンピュータに頼んだらどうでしょう。

「牛乳を買ってきて」と入力するだけでは、普通のプログラムは動きません。どこから商品情報を取得するのか、何を牛乳と判断するのか、購入をどう確定するのか。必要な処理を、コンピュータが実行できる形で伝える必要があります。

**人間の言葉は、多少あいまいでも通じる。コンピュータへの指示は、基本的にそうはいかない。**

そこで登場するのが、プログラミング言語です。

## 1. コンピュータに伝わる「書き方」がある

人間同士でも、伝え方にはルールがあります。

例えば、料理のレシピに「材料を混ぜる」とだけ書いてあったら、何を、どの順番で、どれくらい混ぜるのか分からないかもしれません。

プログラムも同じです。処理の内容だけでなく、**どんな順序で、どんな条件で実行するか**を明確にします。

例えば、Python（パイソン）というプログラミング言語なら、こんなふうに書けます。

```python
price = 120
quantity = 3

total = price * quantity
print(total)
```

このプログラムは、商品の単価を `120`、個数を `3` として、掛け算の結果を表示します。実行結果は `360` です。

ここで大切なのは、英語のように見える単語にも、それぞれ役割があることです。

| 書き方 | 意味 |
| --- | --- |
| `price = 120` | `price` という名前に値を結びつける |
| `quantity = 3` | `quantity` という名前に個数を結びつける |
| `price * quantity` | 2つの値を掛け算する |
| `print(total)` | `total` の値を画面に表示する |

`price` や `quantity` のような名前は、プログラムを書く人が決めています。一方、`print` のように言語が用意している機能や、括弧の付け方などには決まりがあります。

この**書き方の決まり**を、プログラミング言語の「構文（文法）」と呼びます。

## 2. 句読点ひとつで、意味が変わる

日本語でも、句読点の位置によって文章の意味が変わることがあります。

プログラミング言語では、括弧や記号、字下げなどが、さらに重要な意味を持ちます。

例えば、Pythonで次のように書いたとします。

```python
if total >= 300:
    print("送料無料")
```

これは「合計が300以上なら、『送料無料』と表示する」という意味です。

`if` は条件を示し、`>=` は「以上」を表します。行末の `:` と、その次の行の字下げも、Pythonでは文法の一部です。

もし字下げをなくすと、Pythonは処理のまとまりを正しく読み取れず、エラーになります。

```python
# Pythonでは、この書き方はエラーになる
if total >= 300:
print("送料無料")
```

人間なら「たぶんこういう意味だろう」と補えることも、通常のプログラミング言語では、決められたルールに沿って書く必要があるのです。

!!! note "言語によって文法は違う"
    Pythonでは字下げが処理のまとまりを表しますが、ほかの言語では `{ }` のような記号を使うこともあります。どちらが正しいというより、**言語ごとに約束事が違う**のです。

## 3. 書いた命令はどう実行される？

プログラミング言語で書いた命令は、処理系によってコンピュータが実行できる形に変換されます。ここでは、文法に沿って命令を書くことが、その処理の出発点になると覚えておきましょう。

## 4. なぜプログラミング言語は、こんなにたくさんある？

Python、JavaScript、Java、C、C#……。プログラミング言語には、さまざまな種類があります。

「コンピュータへの指示なら、一つの言語に統一すればいいのに」と思うかもしれません。

でも、人間が使う道具にも、目的に応じた違いがあります。包丁とハサミは、どちらも何かを切る道具ですが、得意な仕事が違います。

プログラミング言語も、**何を作りやすくしたいか、どんな制約を重視するか**によって設計が異なります。

| 言語の例 | よく使われる場面 |
| --- | --- |
| Python | データ処理、AI、業務の自動化など |
| JavaScript | Webページの動き、Webアプリなど |
| C | OSや組み込み機器に近い処理など |
| Java / C# | 業務システムやアプリケーションなど |

もちろん、これは用途を限定する表ではありません。一つの言語で多様なものを作れますし、同じ目的を複数の言語で実現することもできます。

言語が違っても、**値を扱う、条件で処理を分ける、同じ処理を繰り返す**といった基本的な考え方には共通点があります。

だから、一つの言語で身につけた考え方は、別の言語を学ぶときにも役立ちます。

## 5. 文法を覚えれば、プログラムは書ける？

ここまで読むと、プログラミングは「コンピュータ用の言葉を覚えること」に見えるかもしれません。

でも、それだけではありません。

例えば、「3個買ったら合計金額を計算する」という処理なら、必要な手順は比較的簡単です。

一方、「注文を受け付けるシステム」を作るなら、在庫がない場合はどうするか、途中で通信が切れたらどうするか、二重注文を防ぐにはどうするか、といったことも考えなければなりません。

**文法は、考えた手順をコンピュータに伝えるための道具。何をどう処理するかを考えることが、プログラミングのもう一つの中心です。**

これは外国語に少し似ています。単語や文法を知っているだけでなく、相手に何を伝えたいのかが大切なのです。

:::tip[今日のなるほど]
**プログラミング言語は、コンピュータに仕事を頼むための「共通の約束事」です。**

人間が読み書きしやすい形で処理を記述し、言語の処理系がそれを実行につなげます。

そして、本当に大切なのは文法の暗記だけではなく、**やりたいことを、小さく明確な手順に分ける力**です。
:::

## おわりに ― コンピュータは、行間を読まない

「帰りに牛乳を買ってきて」

最初のお願いを思い出してみましょう。

人間なら、頼まれていない細かな判断を自然に補います。コンピュータに同じような仕事を任せるには、その判断をどこまで、どんなルールで行うのかを考える必要があります。

プログラミング言語は、その考えを形にするための手段です。

最初は記号だらけに見えるコードも、一つひとつの意味が分かると、**誰かが考えた手順を記した文章**として読めるようになります。

次にコードを見かけたら、「この命令は、何をさせようとしているんだろう」と眺めてみてください。

そこから、プログラミングの世界が少しずつ見えてきます。
