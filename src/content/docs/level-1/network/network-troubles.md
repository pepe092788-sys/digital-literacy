## 昨日まで開けたサイトが、今日は開けない

朝、会社のPCでいつもの業務システムを開こうとしたら、画面がなかなか表示されません。

「ネットにつながらないのかな」

そう思ってニュースサイトを開くと、こちらは普通に表示されます。隣の席の人に聞くと、同じ業務システムが開けないそうです。

ネットにつながっているのか、いないのか。いったい、どちらなのでしょう。

この疑問は、インターネットの仕組みを知る入り口になります。普段は一つの動作に見える「サイトが開く」も、実は**いくつもの機械と通信が、順番に働いた結果**だからです。

## サイトを開くとき、PCは何をしている？

Webサイトの文章や画像は、通常、どこかにある別のコンピュータに保存されています。そのように、利用者の要求に応じてデータを提供するコンピュータを**サーバー**と呼びます。

ブラウザでページを開くとき、PCは画面に情報が自然に現れるのを待っているわけではありません。おおまかには、次のやり取りをしています。

1. **リクエスト（要求）を送る。** PCのブラウザが、相手のサーバーに「このページのデータをください」と要求する。
2. **サーバーが要求を受け取る。** サーバーは要求されたページを探したり、必要な処理を行ったりする。
3. **レスポンス（応答）を返す。** サーバーが、ページのデータや処理結果をPCへ送り返す。ページが見つからなければ、エラーを表す応答を返すこともある。
4. **ブラウザが画面に表示する。** PCが受け取ったデータを読み取り、文章や画像などを表示する。実際のページでは、画像などを取得するために追加のリクエストも行われる。

```text
自分のPC                          相手のサーバー
   │                                    │
   │──── リクエスト：ページをください ────→│
   │                                    │
   │←─── レスポンス：ページのデータ ──────│
   │                                    │
  ブラウザが表示する
```

ここで一つ分かることがあります。**サイトが開かないのは、必ずしも「インターネット全体が止まった」という意味ではない**のです。要求が届かない場合も、サーバーが応答できない場合も、応答が戻ってこない場合もあります。

## リクエストは、どうやって遠くの相手へ届く？

では、会社のPCから送ったリクエストは、遠くのサーバーまでどうやって届くのでしょう。

PCとサーバーが一本のケーブルで直接つながっているとは限りません。まず社内のネットワークを通り、通信会社などが管理するネットワークを経由して、相手側のネットワークへと進みます。途中の機器が、データを次の行き先へ送り出しています。

```text
会社のPC
   │
社内ネットワーク
   │
通信会社などのネットワーク
   │
別の組織のネットワーク
   │
業務システムのサーバー
```

これは単純化した一例です。実際の経路は接続先や通信状況によって異なり、複数のネットワークを通ることがあります。応答もネットワークを通ってPCへ戻りますが、必ずしも要求と同じ道を通るとは限りません。

一つの巨大な機械がすべてを仲介しているのではありません。**それぞれの組織が管理するネットワークが、共通の通信の決まりに従ってつながっている。** この世界規模のつながりが、インターネットです。

## 障害の起き方が違うのは、なぜ？

最初の場面に戻りましょう。業務システムは開けないのに、ニュースサイトは開けました。

二つのサイトは、必ずしも同じサーバーに置かれていません。通信の途中で使う設備や経路も、すべてが同じとは限りません。だから、片方に関係する部分で問題が起きても、もう片方は正常に利用できることがあります。

別の場面も考えてみます。

**自分のPCだけ、どのサイトも開けない。** ほかの人は使えているなら、まず自分のPCや、自分が利用している接続部分に注目できます。ただし、それだけで原因が確定するわけではありません。

**同じオフィスの全員が、どのサイトも開けない。** それぞれのPCよりも、全員が共通して利用する社内ネットワークや外部への接続部分に問題がある可能性が考えられます。

**ニュースサイトは開けるが、業務システムだけ開けない。** 少なくとも、すべての通信が止まっているわけではありません。業務システム側のサーバー、そのサービスに至る通信経路、あるいはサービス固有の処理などに目を向けられます。

これらは障害対応の正解集ではありません。実際には、名前から通信先を探す仕組みやアクセス制御など、ほかにも関係する要素があります。それでも、**どこまで動いていて、何が共通して失敗しているのか**を考えると、見えない構造を少しずつ捉えられます。

## 「ネットにつながらない」は、一つの状態ではない

普段、私たちは「サイトが開いた」という結果だけを見ています。その裏で、PCがリクエストを送り、複数のネットワークがデータを運び、サーバーがレスポンスを返していることは、意識する必要がありません。

けれど、障害が起きると、それまで一つに見えていたものが分かれて見えます。

自分のPCの問題なのか。途中のネットワークなのか。通信相手のサーバーなのか。あるいは、サーバーが返した結果をブラウザが表示する段階なのか。

「ネットにつながらない」という言葉は便利ですが、実際にはこうした**異なる場所で起きる、異なる問題**をひとまとめにしています。

そして、この違いが生まれること自体が、インターネットの正体を教えてくれます。

:::tip[今日のなるほど]
**インターネットは、どこか一か所にある巨大な装置ではない。**

自分のPCから送ったリクエストが、いくつものネットワークを経由して相手のサーバーへ届き、レスポンスが返ってくる。その通信を可能にしている、ネットワーク同士のつながりがインターネットです。

だから「ネットにつながらない」にも、いろいろな起き方がある。障害は、普段は見えない通信の仕組みを浮かび上がらせるのです。
:::
