AIを使って、自分の欲しいプログラムを作ることができる時代になりました。

例えば、パスワードを使ってデータベースに接続し、必要な情報を取得するプログラムを作ったとします。

パスワードをプログラムに直接書き込めば、毎回入力する必要もなく、手軽に利用できます。

しかし、この便利な方法には、セキュリティ上の問題が潜んでいます。

今回は、その問題に関係する「ハードコード」という概念について考えてみましょう。

## ハードコードとは何か

コンピューターに対する命令が書かれた文章を、ソースコードと呼びます。

ソースコードには、コンピューターに何をさせるのかという命令だけでなく、処理に使用する値も記述できます。

例えば、パスワードをソースコードに直接書き込むと、次のようになります。

```python
password = "example-password"
```

プログラムは、このソースコードに書かれているパスワードを使って接続を行います。

このように、プログラムで使用する値をソースコードに直接書き込み、固定することを**ハードコード**と呼びます。

パスワードを別途設定する必要がないため、プログラムを手軽に動かすことができます。

しかし、プログラムが動くことと、安全であることは別の話です。

## ソースコードはどのように扱われるのか

ソースコードは、プログラムを動かすためだけに存在するものではありません。

プログラムを修正するために読み返したり、他の人に渡したり、AIに修正を依頼するために送信したりすることもあります。

自分が作った便利なプログラムを、インターネット上で公開することもあるでしょう。

つまり、ソースコードは、開発や共有の過程でさまざまな場所にコピーされる可能性がある情報です。

一方、パスワードはどうでしょうか。

パスワードは、本来、限られた人やシステムだけが利用できるように管理する情報です。

ソースコードとパスワードでは、情報の性質が異なります。

## なぜハードコードが危険なのか

パスワードをハードコードすると、ソースコードの中にパスワードが含まれることになります。

例えば、作成したプログラムのソースコードを同僚に渡したとします。

自分としては、プログラムの処理内容を共有しただけのつもりでも、パスワードが書き込まれていれば、それも一緒に渡していることになります。

インターネット上に公開した場合も同じです。

プログラムを公開したつもりが、パスワードまで公開してしまう可能性があります。

また、第三者によってソースコードが盗まれた場合にも、そこに記述されたパスワードが一緒に流出します。

流出したパスワードによって第三者がシステムに接続できれば、情報を盗まれたり、データを書き換えられたりする可能性があります。

ハードコードすることで、ソースコードと秘密情報が一体化してしまう。

これが、パスワードをハードコードすることの危険性です。

## ソースコードとパスワードを分離する

では、パスワードをソースコードに書き込まなければ、プログラムはどのように接続するのでしょうか。

実は、プログラムがパスワードを使用することと、ソースコードにパスワードを書き込むことは、必ずしも同じではありません。

例えば、プログラムを起動したときにパスワードを入力する仕組みにすることもできます。

あるいは、適切に管理された別の場所にパスワードを保管しておき、プログラムが動作するときに取得することもできます。

ソースコードには、パスワードそのものではなく、パスワードを取得して使用するための命令を書いておくのです。

このようにすれば、パスワードがソースコードに含まれていなくても、プログラムは必要な処理を行えます。

そして、ソースコードを他人に渡しても、それだけでパスワードまで渡してしまうことはありません。

## 情報を分離することは、リスクを分離すること

ソースコードとパスワードを分離したとしても、パスワードがどこかに存在することに変わりはありません。

では、分離することにどのような意味があるのでしょうか。

重要なのは、二つの情報を別々に管理できるようになることです。

ハードコードされている場合、ソースコードを閲覧できる人は、そこに書かれているパスワードも閲覧できます。

しかし、パスワードを分離して適切に管理すれば、ソースコードを閲覧できる人と、パスワードを利用できる人を分けることができます。

もちろん、パスワードを保管している場所から情報が流出する可能性は残ります。

分離しただけで、すべての危険がなくなるわけではありません。

それでも、ソースコードが流出したという一つの問題が、そのままパスワードの流出につながる事態を防ぎやすくなります。

**情報を分離することは、リスクを分離することでもあるのです。**

## ハードコードはすべて悪いのか

ここまで読むと、ソースコードに値を直接書き込むこと自体が悪いように感じるかもしれません。

しかし、必ずしもそうではありません。

例えば、分を秒に変換するプログラムでは、1分が60秒であることを利用します。

この60という値は、秘密にする必要もなく、変更されることも通常はありません。

そのため、ソースコードに直接記述しても問題ありません。

一方、ファイルの保存場所を直接記述すると、別のパソコンで動かなくなる場合があります。税率などの変更される可能性がある値を直接記述すると、そのたびにソースコードを修正する必要があります。

ハードコードによる問題は、記述する情報の性質によって異なります。

特にパスワードのような秘密情報については、使いやすさだけでなく、安全性を考慮して管理する必要があります。

## AIにコーディングを任せる時代だからこそ

AIにプログラムの作成を依頼するとき、パスワードを直接書き込む方法は手軽に感じられるかもしれません。

別途パスワードを設定する手間がなく、すぐにプログラムを動かせるからです。

しかも、ハードコードされていても、プログラムは正常に動作します。

画面を見ているだけでは、セキュリティ上の問題があることに気づけない場合もあります。

しかし、プログラムが正常に動くことは、そのプログラムが安全であることを意味しません。

人間がすべてのソースコードを書ける必要はありません。

パスワードを分離する具体的な方法を知らなくても、なぜ分離する必要があるのかを理解していれば、AIに秘密情報を直接書き込まない設計を依頼できます。

実際のパスワードをAIに伝えず、後から自分で設定できる仕組みにすることもできます。

プログラムを書く技術と、プログラムが適切に作られているかを判断するための知識は、異なるものです。

AIにコーディングを任せられる時代だからこそ、設計の理由を理解することにも価値があるのではないでしょうか。

## 今日のなるほど

ハードコードとは、プログラムで使用する値をソースコードに直接書き込み、固定することです。

パスワードをハードコードすると、ソースコードとパスワードが一体化し、一緒に流出する可能性があります。

これらを分離すれば、それぞれを異なる方法で管理できるようになります。

大切なのは、単にプログラムを動かすことだけではなく、どのような情報が、どこに存在しているのかを考えることです。

**情報を分離することは、リスクを分離することでもあるのです。**
