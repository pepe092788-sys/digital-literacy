最近、インターネット上のサービスで、パスワードの代わりにパスキーを使うよう勧められることが増えてきました。

顔認証や指紋認証だけでログインでき、パスワードよりも安全だといわれています。

しかし、パスワードを廃止してパスキーに置き換えたところで、今度はパスキーが攻撃者の標的になるだけではないのでしょうか。

新しい認証技術だからといって、安全であるとは限りません。

パスキーの仕組みを知りながら、なぜ置き換えることに意味があるのかを考えてみましょう。

## パスキーとは

パスキー（Passkey）とは、パスワードを入力する代わりに、暗号技術を利用して本人の認証を行う仕組みです。

スマートフォンの顔認証や指紋認証、パソコンのPINなどを使ってログインできます。

ただし、パスワードを顔認証に置き換えただけではありません。

パスワードとパスキーでは、本人であることを証明する方法そのものが異なります。

| 認証方式 | 本人であることの確認方法 |
| --- | --- |
| パスワード | 正しい秘密の文字列を知っている |
| パスキー | 登録された秘密鍵を使って正しい証明を作れる |

パスキーを登録する際には、数学的に対応する2つの鍵が作られます。

| 鍵 | 役割 |
| --- | --- |
| 秘密鍵 | 利用者側で管理し、本人であることを証明するために使う |
| 公開鍵 | サービス側で管理し、証明が正しいか確認するために使う |

顔認証や指紋認証は、秘密鍵を使用してよいかを端末側で確認するためのものです。

顔や指紋の情報をログイン先のサービスに送っているわけではありません。

## 秘密を伝えずに本人であることを証明する

一般的なパスワード認証では、入力されたパスワードをサービス側が暗号化された通信を通じて受け取り、正しいものかを確認します。

一方、パスキー認証では、秘密鍵そのものをログイン先のサービスに送信しません。

その代わり、サービス側から毎回異なる確認用データが送られてきます。

利用者の端末は、その確認用データを含む認証データと秘密鍵を使って、電子署名と呼ばれる証明を作成します。

サービス側は、受け取った電子署名を公開鍵で検証します。

| 順序 | 処理 |
| --- | --- |
| ① | サービスが今回限りの確認用データを送る |
| ② | 端末が顔認証などで利用者を確認する |
| ③ | 端末が秘密鍵を使って電子署名を作る |
| ④ | 端末が電子署名などの認証データをサービスに送る |
| ⑤ | サービスが公開鍵で署名を検証し、確認用データなども照合する |

確認用データが毎回変わるため、過去の電子署名を盗まれても、次回の認証にはそのまま利用できません。

このような認証方法を、チャレンジレスポンス認証と呼びます。

## 正解を知らないのに、なぜ正しいと判断できるのか

秘密鍵をサービス側に送らないのであれば、サービス側はどうやって電子署名が正しいと判断するのでしょうか。

ここでは、RSAという暗号方式を極端に簡略化した計算を使って考えてみます。

次の2つの計算ルールを用意します。

- 秘密鍵：7乗して33で割った余りを求める
- 公開鍵：3乗して33で割った余りを求める

まず、サービス側が確認用データとして「4」を送ります。

利用者の端末は、4を7乗して33で割った余りを求めます。

4の7乗は16384です。これを33で割ると、余りは16になります。

この「16」を電子署名としてサービス側に送ります。

今度は、サービス側が受け取った16を3乗して33で割ります。

16の3乗は4096です。これを33で割ると、余りは4になります。

最初に送った数字と一致しました。

| 処理 | 結果 |
| --- | ---: |
| サービスが送った数値 | 4 |
| 秘密鍵を使った計算 | 16 |
| 公開鍵を使った検証 | 4 |

サービス側は、電子署名の正解が16であることを事前に知る必要がありません。

受け取った電子署名を検証した結果が、最初に送った数値と一致するかを確認すればよいのです。

つまり、**正解を作る能力と、正解かどうかを確認する能力を分離している**わけです。

実際の電子署名には、ハッシュ化や安全な符号化など、さらに複雑な処理が使われています。また、パスキーではRSA以外の署名方式も利用され、元の数値に戻すのではなく数学的な等式が成り立つか確認するものもあります。この例は、署名と検証の関係を理解するための簡略例であり、この小さな数値や計算方法を実際の認証に使うことはできません。

## 公開鍵を盗めば攻略できるのではないか

秘密鍵を盗むことが難しいのであれば、攻撃者は公開鍵を狙うのではないでしょうか。

実は、公開鍵は第三者に知られることを想定した情報です。

公開鍵を手に入れた攻撃者は、作成した電子署名が正しいかどうかを検証できます。

しかし、正しい電子署名を簡単に作れるわけではありません。

先ほどの計算例では、数字が小さいため、さまざまな数字を試していけば正解の16を見つけられます。

実際の暗号技術では、このような逆算や署名の偽造が極めて困難になるように設計されています。

## 攻略するのは、どれほど難しいのか

パスキーで利用される代表的な暗号方式の一つに、P-256という楕円曲線を利用した電子署名方式があります。

この方式は、古典的なコンピュータによる既知の攻撃に対して、約128ビットの安全強度を持つと評価されています。

これがどの程度の規模なのか、完全にランダムなパスワードの組み合わせ数と比較してみましょう。

| 認証情報 | 探索・計算規模の目安 |
| --- | ---: |
| 数字4桁のパスワード | 1万 |
| 数字8桁のパスワード | 1億 |
| 英数字8文字のパスワード | 約218兆 |
| 英数字12文字のパスワード | 約3.23×10²¹ |
| パスキー（P-256を使う場合）の暗号強度 | 約3.40×10³⁸ |

英数字は、大文字・小文字・数字の62種類を使うものとします。パスキーの数値は鍵の候補数そのものではなく、128ビットの安全強度に相当する計算量（2の128乗）の規模を示しています。

仮に、1秒間に1兆回もの必要な暗号演算を実行できるコンピュータがあったとしましょう。

128ビットの安全強度に相当する計算規模に達するには、およそ1080京年かかる計算になります。

宇宙の年齢が約138億年とされていることを考えると、途方もない規模です。

これは計算量の大きさを理解するための仮定であり、実際の攻略時間を保証するものではありません。パスワードの照合と暗号演算では、一回の処理に必要な計算量も異なります。

十分に長くランダムなパスワードも高い強度を持ちます。しかし、人間が覚えやすい文字列を選ぶ傾向や、使い回しといった問題があります。

パスキーでは、暗号学的に安全な鍵をコンピュータが生成するため、人間の記憶力に頼らずに高い暗号強度を確保できます。

## 暗証番号式のドアと鍵式のドア

身近なものに例えると、暗証番号式のドアと鍵式のドアの違いに似ています。

暗証番号式のドアでは、誰かが番号を入力するところを盗み見れば、同じ番号を使ってドアを開けられます。

一方、鍵式のドアでは、誰かがドアを開ける様子を見ただけで、対応する鍵を手に入れられるわけではありません。

鍵穴の構造を調べて合鍵を作ることも考えられますが、そのためには別の技術や労力が必要です。

パスキーは、この合鍵を作る難しさを数学によって極端に高めたものと考えることができます。

ただし、実際のパスキーでは物理的な鍵を差し込むのではなく、電子署名によって鍵の所持を証明します。

## パスワード認証の弱点を減らす

パスキーの利点は、暗号技術の強度だけではありません。

認証情報の盗まれ方にも違いがあります。

| 攻撃やリスク | パスワード | パスキー |
| --- | --- | --- |
| 認証情報の推測 | 覚えやすい文字列などが狙われる | 暗号学的に安全な鍵を使う |
| 認証情報の使い回し | 他のサービスでも悪用され得る | サービスごとに異なる鍵を使う |
| 偽のログインサイト | 入力したパスワードが盗まれ得る | 正規サービス用の鍵は原則として使えない |
| サーバーの認証情報の流出 | パスワードのハッシュ値が解析され得る | 公開鍵だけでは有効な署名を作ることは極めて困難 |
| 過去の認証データの盗難 | パスワード自体を入手されれば再利用される | 過去の署名は次回の認証にそのまま使えない |

パスキーに置き換えることで、従来のパスワード認証に対して成立していた攻撃の多くが通用しにくくなります。

## では、パスキーが安全なら他の対策は不要なのか

もちろん、そうではありません。

例えば、ドアの鍵穴を含む錠前そのものを交換されてしまったらどうでしょうか。

どれだけ合鍵を作ることが難しくても、錠前を交換されれば、元の鍵の強度は関係なくなります。

パスキーでも同じように、サーバーの認証情報や検証処理が不正に変更された場合には、認証を突破される可能性があります。

また、端末の乗っ取り、アカウント復旧手続きの悪用、ログイン後のセッションの窃取など、暗号技術以外を狙う攻撃も存在します。

パスワードによるログインを代替手段として残している場合は、パスワード側の弱点も残ります。

パスキーは、システム全体の安全性を保証する万能な技術ではありません。

## 攻撃者が新しい技術を狙うことに変わりはない

パスキーが普及すれば、攻撃者もパスキーを利用するシステムに対して、新しい攻撃方法を考えるようになるでしょう。

そう考えると、認証方式を変えるだけでは根本的な解決にならないようにも思えます。

しかし、攻撃の対象が変わることと、攻撃の難易度が変わらないことは別の話です。

これまで比較的少ない労力で成立していた攻撃が通用しなくなれば、攻撃者は別の経路を探す必要があります。

暗号そのものを正面から破ろうとすれば、時間や費用が大きく増えます。残された弱点に対しても別の対策を重ねれば、攻撃者が選べる手段はさらに限られます。

セキュリティ対策の価値は、攻撃を完全になくすことだけにあるのではありません。

攻撃者が利用できる手段を減らし、攻撃を成立させるための負担を大きくすることにもあります。

:::tip[今日のなるほど]
パスキーに変えれば、絶対に安全になるわけではありません。

しかし、パスワードからパスキーへの移行は、単に攻撃の対象を別のものに置き換えているわけでもありません。

**従来の認証情報を狙う攻撃を成立させるための難易度を、桁違いに引き上げているのです。**

この視点を持つと、セキュリティ対策とは何のために行うものなのか、少し見え方が変わってきます。
:::
