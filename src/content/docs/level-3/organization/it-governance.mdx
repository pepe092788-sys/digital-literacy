ある会社が、業務の効率化を進めるため、各部署にITの積極的な活用を呼びかけました。

営業部は顧客管理システムを導入しました。

製造部は生産管理システムを導入しました。

総務部は書類の作成に生成AIを活用し始めました。

それぞれの部署では、業務の効率化が進んでいます。

しかし、会社全体を見渡してみると、同じ情報が複数のシステムに保存され、似た機能を持つサービスに重複して費用を支払っています。

誰がどのサービスを利用しているのか、会社として把握できていないものもあります。

それぞれの部署がITを上手に活用することと、会社全体がITを上手に活用することは、同じなのでしょうか。

## ITガバナンスとは

ガバナンス（Governance）とは、日本語で「統治」と訳される言葉です。

ITガバナンスとは、組織の目的を達成するために、ITの活用方針を定め、適切な意思決定や監督が行われるようにする仕組みです。

単にITの利用を制限することではありません。

ITによってどのような価値を生み出すのか、そのためにどのような投資を行い、どのようなリスクを管理するのかを、組織として考えることです。

## 部分最適と全体最適

冒頭の会社では、それぞれの部署が自分たちの業務を効率化しようとしていました。

個々の部署にとっては合理的な判断です。しかし、それが会社全体にとっても最適な判断であるとは限りません。

<ITGovernanceDiagrams kind="optimization" />

このように、個々の部分にとって最適な状態を目指すことを「部分最適」、全体にとって最適な状態を目指すことを「全体最適」と呼びます。

ITガバナンスは、部分最適だけでは解決できない問題に対して、組織全体の視点を持つための仕組みでもあります。すべての部署に同じシステムを使わせるという意味ではなく、各部署の必要性を尊重しつつ、組織全体の目的との整合性を考えます。

## ITガバナンスが扱うもの

ITガバナンスの対象は、情報セキュリティだけではありません。

| 視点 | 考えるべきこと |
| --- | --- |
| 経営戦略 | ITの活用は会社の目的に合っているか |
| 投資効果 | 投資に見合った価値を得られているか |
| リスク | 情報漏洩やシステム停止に備えているか |
| 資源管理 | 人材や予算、システムを適切に活用しているか |
| 法令遵守 | 法律や契約に反していないか |
| 責任と権限 | 誰が判断し、誰が責任を負うのか |

例えば、非常に安全なシステムを導入したとしても、そのシステムが業務に必要とされていなければ、適切なIT投資だったとは言えません。

反対に、大きな業務改善効果が期待できても、重大なリスクが放置されていれば、組織として適切な活用ができているとは言えません。

価値とリスクの両方を考える必要があります。

## 評価・指示・モニタリング

では、具体的にどのようにITガバナンスを機能させるのでしょうか。

経済産業省の「システム管理基準」では、経営陣によるガバナンスの活動として、評価・指示・モニタという三つの行動が示されています。

<ITGovernanceDiagrams kind="cycle" />

### 評価（Evaluate）

現在の状況や課題、期待できる効果、リスクなどを評価します。

例えば、新しいシステムを導入するなら、それが本当に会社の課題を解決するのかを考えます。

### 指示（Direct）

評価した結果をもとに、組織としての方向性や方針を決め、必要な責任と権限を割り当てます。

例えば、システムの導入目的や予算、利用条件、担当責任者を定めます。

### モニタリング（Monitor）

決められた方針に沿ってITが活用されているか、期待した成果が得られているかを確認します。

期待した効果が得られていなければ、その原因を考え、必要に応じて方針を見直します。

ガバナンスは、一度ルールを作れば完成するものではありません。

状況の変化に合わせて、継続的に機能させる必要があります。

参考：[経済産業省「システム管理基準」（令和5年4月改訂版・PDF）](https://www.meti.go.jp/policy/netsecurity/sys-kansa/sys-kanri-2023.pdf)

## ITガバナンスとITマネジメント

ガバナンスと似た言葉に、マネジメント（Management）があります。

両者は密接に関係していますが、役割が異なります。

<ITGovernanceDiagrams kind="roles" />

ガバナンスが組織としての方向性と監督を担い、マネジメントがその方向性に沿った活動を実行します。マネジメントも担当する活動の進捗や結果を確認し、その情報をガバナンスの判断につなげます。

参考：[ISACA「COBIT」](https://www.isaca.org/en/resources/cobit)

## セキュリティとの違い

情報セキュリティは、情報やシステムを守るための活動です。

一方、ITガバナンスは、安全性を含めたIT活用全体の方向性を定め、監督するための仕組みです。

| 分野 | 主な関心 |
| --- | --- |
| ITガバナンス | 組織としてITをどう活用し、統治するのか |
| ITマネジメント | ITに関する活動をどう計画し、実行するのか |
| セキュリティ | 情報やシステムをどう守るのか |

例えば、会社が多要素認証の導入を求める方針を決めることはガバナンスに関わり、具体的な認証方法を選択して導入・運用することはマネジメントに関わります。そして多要素認証そのものはセキュリティ対策です。

これらは別々の役割を持ちながら、互いに関係しています。

## AI時代のITガバナンス

従来、新しい業務システムを導入するには、専門的な知識や開発費用が必要になることが多くありました。

生成AIやノーコード開発ツールによって、専門の開発部門に依頼せず、現場の従業員が業務用のアプリケーションを作れる場面も増えています。

これは業務改善の可能性を広げる一方で、組織として新たな課題を生み出します。

誰がどのようなシステムを作っているのか。

機密情報は適切に扱われているのか。

作成した従業員が異動・退職した後は、誰がシステムを管理するのか。

こうした問題に対応するためには、IT活用を禁止するのではなく、現場の創意工夫を生かしながら、適切な管理が行われる仕組みを整えることが重要です。

これは、シャドーITやシャドーAIの問題にもつながります。

## 今日のなるほど

冒頭の会社では、それぞれの部署がITを活用して業務を改善していました。

しかし、会社全体としての方針や情報の管理、投資の判断が十分に整っていませんでした。

ITガバナンスは、こうした個々の活動を組織全体の目的につなげるための仕組みです。

ITを安全に使うことも、ITによって新しい価値を生み出すことも、その対象になります。

**ITガバナンスとは、ITを使わせないための仕組みではなく、組織としてITを適切に活用するための仕組みなのです。**
