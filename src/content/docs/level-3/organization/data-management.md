ある会社が、蓄積してきた業務データを使って配送業務を改善しようとしました。

しかし、拠点ごとに荷役時間の計測方法が異なり、同じ取引先にも異なる名称が登録されています。過去の記録がどこにあるのか分からない場合もあります。

データは十分にあるはずなのに、拠点間の比較や分析がうまくできません。

データを持っていることと、活用できることは、何が違うのでしょうか。

## データマネジメントとは

データマネジメント（Data Management）とは、データを組織の資産として捉え、継続的に正しく、安全に、価値のある形で利用できるように管理する活動です。

単にデータを保存することではありません。収集から利用、廃棄までのライフサイクル全体を対象とします。

| 段階 | 管理すること |
| --- | --- |
| 収集 | 必要な情報を、意味や記録方法を定めて取得する |
| 保存 | 適切な場所と形式で保管する |
| 整備 | 誤りや重複、表記ゆれを確認し改善する |
| 活用 | 分析、業務、意思決定、AIなどに利用する |
| 保管・廃棄 | 必要な保存期間を定め、不要になった情報を適切に削除する |

これらは必ずしも一方向の手順ではありません。利用する中で品質の問題が見つかれば、収集方法や管理のルールを見直すこともあります。

## 同じデータでも、意味が違うことがある

例えば、ある拠点ではトラックが到着してから荷役が終わるまでを「荷役時間」として記録し、別の拠点では実際に荷物を積み降ろししている時間だけを記録しているとします。

どちらも正しく記録していても、その数値をそのまま比較することはできません。

記録の意味を定め、どこから取得した情報なのかを把握し、必要に応じて定義を統一することで、初めて比較できるデータになります。

つまり、データの品質は誤字や入力ミスの少なさだけではなく、利用する目的に適しているかどうかにも関わります。

## データマネジメントが扱う領域

| 領域 | 役割 |
| --- | --- |
| データ品質 | 正確性、欠損、重複、鮮度などを管理する |
| データセキュリティ | アクセス権限や情報漏洩のリスクを管理する |
| マスターデータ管理 | 顧客・商品などの共通する基本情報を整える |
| メタデータ管理 | データの意味、所在、作成元などを把握できるようにする |
| データアーキテクチャ | データの構造やシステム間の関係を設計する |
| データ統合 | 異なるシステムの情報を連携させる |
| データガバナンス | 管理方針や責任、意思決定の仕組みを整える |

こうした領域を体系的に整理した代表的な知識体系にDAMA-DMBOKがあります。この表はその全領域を列挙したものではなく、理解のために主な活動を整理したものです。

## データガバナンスとの違い

データガバナンスは、組織としてデータをどのように扱うべきかを定め、責任を明確にし、適切に管理されているかを監督する仕組みです。

例えば、取引先情報の管理責任者を決め、登録や変更の方針を定めることはガバナンスに関わります。その方針に沿って重複を解消し、情報を更新することはマネジメントの実務に関わります。

データガバナンスは、広い意味でのデータマネジメントを方向づける重要な領域です。方針を定めるだけでも、個別のデータを整備するだけでも、継続的な管理は難しくなります。

組織として技術の活用を統治する考え方については、[ITガバナンス](../it-governance/)にも共通点があります。

## AI・DXの土台になる理由

冒頭の会社が、荷役時間をもとにAIで配送計画を改善しようとしたらどうでしょう。

記録の定義が違えば、AIが分析した結果に、実際の業務効率ではなく計測方法の違いが反映されてしまう可能性があります。

高性能なAIを導入しても、元のデータの意味や品質が自動的に保証されるわけではありません。

一方で、データの意味や品質、利用できる範囲が明確になっていれば、分析結果を検証し、業務改善に結びつけやすくなります。

データマネジメントはIT部門だけの仕事でもありません。荷役時間の意味を理解している業務部門、活用の目的を決める経営層、データを扱う仕組みを整える技術部門が、それぞれ関わります。

## 今日のなるほど

冒頭の会社に足りなかったのは、必ずしもデータの量ではありません。組織として、そのデータの意味を理解し、信頼して利用できるようにする仕組みでした。

**データマネジメントとは、蓄積されている情報を、組織が信頼して活用できる資産にするための活動なのです。**
