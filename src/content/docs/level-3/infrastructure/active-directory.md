会社のパソコンを使っていると、自宅のパソコンとは少し違うことに気づきます。

壁紙を変更できなかったり、一定時間で画面がロックされたり、ソフトウェアを自由にインストールできなかったりします。一方、別の管理対象パソコンでも、同じ会社のアカウントでサインインできることがあります。

こうした設定を、情報システムの担当者が一台ずつ行っているのでしょうか。

企業のWindows環境では、ユーザーやコンピュータをまとめて管理するために、**Active Directory（アクティブディレクトリ、略してAD）** が利用されることがあります。この記事では、主にWindows ServerのActive Directory Domain Services（AD DS）を扱います。

## 1. 一台ずつ管理すると何が起きるのか

社員100人、パソコン100台の会社を想像してみましょう。

各パソコンのローカルアカウントだけで運用する場合、必要な端末ごとにアカウントや設定を管理することになります。社員が異動したり退職したりすると、関係する端末やサービスの設定を見直さなければなりません。

管理する対象が増えるほど、手間だけでなく、設定漏れや権限の消し忘れも起こりやすくなります。

そこで、ユーザーやコンピュータに関する情報を共通の場所にまとめ、複数の端末やサービスがそれを利用できるようにします。

```text
個別管理
  PC A：アカウント・設定
  PC B：アカウント・設定
  PC C：アカウント・設定

ADを利用する管理
  Active Directory
   ├─ ユーザー・グループの情報
   ├─ コンピュータの情報
   └─ 共通設定を適用する仕組み
        ↓
     PC A・PC B・PC C
```

AD以外にも一元管理する手段はありますが、従来のWindowsドメイン環境を支える代表的な仕組みがAD DSです。

## 2. ADはどのように動くのか

ディレクトリとは、ここではユーザーやコンピュータなどの情報を整理して記録する仕組みのことです。組織内の名簿に似ていますが、単に名前を一覧にするだけではありません。

例えば、社員がドメインに参加したパソコンから会社の共有フォルダを開く場面を考えてみましょう。

1. 社員が会社のアカウントでサインインする。
2. 通常、ドメインコントローラーが認証に関わる処理を行う。
3. 共有フォルダを提供するサーバーが、ユーザーや所属グループに基づいてアクセス権限を確認する。
4. 権限があれば、フォルダを閲覧できる。

実際の認証にはKerberosなどの仕組みが使われます。端末に保存された認証情報でオフラインサインインできる場合もあり、すべての操作で毎回ADに問い合わせるわけではありません。

ここで大切なのは、**本人かどうかを確認する認証と、何をしてよいかを判断する認可は別の仕事**だということです。

ADは認証やグループ情報などを提供し、ファイルサーバーやアプリケーションは、それぞれのアクセス制御の仕組みを使って利用を許可するか判断します。

## 3. ADを構成する言葉

| 用語 | 役割 |
| --- | --- |
| ドメイン | ユーザーやコンピュータを共通のディレクトリで管理する単位 |
| ドメインコントローラー（DC） | ディレクトリ情報を保持し、認証などを提供するサーバー |
| グループ | 複数のユーザーなどをまとめ、権限管理を簡単にする仕組み |
| 組織単位（OU） | ユーザーやコンピュータなどを階層的に整理し、管理を委任したり設定を適用したりする単位 |
| グループポリシー（GPO） | ユーザーやコンピュータに適用する設定をまとめた仕組み |

例えば、経理部の社員一人ひとりに経理用の共有フォルダの権限を付与する代わりに、経理部のセキュリティグループに権限を与えることができます。

社員が異動した場合は、所属するグループを変更することで、関連する権限を管理しやすくなります。

OUは管理対象を整理するためのものであり、OUに所属するだけで共有フォルダへのアクセス権が自動的に与えられるわけではありません。グループとOUは役割が異なります。

## 4. なぜ会社のパソコンには共通のルールがあるのか

ここで登場するのがグループポリシーです。

例えば会社が、離席時に画面を自動でロックするルールを決めたとします。各端末を個別に設定する代わりに、管理者がポリシーを設定し、対象となる端末に適用できます。

| 管理したいこと | 設定の例 |
| --- | --- |
| アカウント | パスワードのルール |
| 画面の安全性 | 一定時間で画面をロックする |
| 外部機器 | USB記憶装置へのアクセスを制限する |
| ソフトウェア | 利用できるアプリや設定変更を制限する |

設定の反映には対象や更新のタイミングなどの条件があります。また、企業によってはADではなく別の端末管理製品で同様の制御を行っている場合もあります。

会社のパソコンで設定を自由に変更できない理由の一つは、個人の使いやすさだけでなく、組織全体で守るべきルールがあるためです。

## 5. 一元管理は便利だが、管理の中心も守る必要がある

社員の入社・異動・退職に合わせて、アカウントやグループを変更できることは、運用の手間を減らし、権限の管理にも役立ちます。

一方、強い管理権限を持つアカウントが悪用されれば、多数の端末やサービスに影響が及ぶ可能性があります。

そのため、必要な人だけに必要な管理権限を与え、管理者アカウントを保護し、更新や監視を行うことが重要になります。アカウントを無効化しても、既存のセッションや連携先への反映には別途対応が必要な場合があります。

**管理を一か所にまとめることは、管理の中心に大きな責任を持たせることでもある**のです。

## 6. Microsoft Entra IDとの違い

Microsoftには、Microsoft Entra ID（旧Azure Active Directory、旧Azure AD）というクラウドのID管理サービスもあります。

| 項目 | AD DS | Microsoft Entra ID |
| --- | --- | --- |
| 主な用途 | Windowsドメインや社内システムの認証・管理 | クラウドアプリなどのID・アクセス管理 |
| 基盤 | Windows Server上のドメインコントローラー | Microsoftが提供するクラウドサービス |
| 代表的な仕組み | ドメイン参加、Kerberos、LDAP、グループポリシー | クラウド認証、シングルサインオン、条件付きアクセスなど |
| 端末設定 | 主にグループポリシーなど | Microsoft Intuneなどの端末管理サービスとの連携 |

両者は連携して利用することもできます。ただしEntra IDはAD DSをそのままクラウドに移したものではなく、対応する認証方式や管理の仕組みが異なります。

## おわりに ― 管理する対象を、個々の機械から組織へ

ADを使うことの意味は、単にパスワードを一か所に集めることではありません。

誰が組織の一員なのか、どの端末が管理対象なのか、どの情報にアクセスできるのか。共通の情報とルールを使って、それらを管理しやすくすることにあります。

:::tip[今日のなるほど]
Active Directoryは、組織内のユーザーやコンピュータを一元的に管理するための基盤です。

認証・アクセス権限・端末設定をそれぞれの仕組みで管理し、組織のルールを複数の端末やサービスに反映しやすくします。
:::
