ある倉庫で、商品の出荷が遅れています。

担当者は仕分けの作業時間が長いことに気づき、AIを利用すれば作業時間を半分にできるという紹介文を見つけました。

もし仕分けが速くなれば、出荷も速くなるのでしょうか。

この一つの問いを考えるとき、私たちは物事を整理し、根拠をもとに判断し、まだ分からないことを確かめています。こうした三つの力を支える考え方を見ていきましょう。

## 物事を整理し、全体を捉える力

### 構造化思考 ― 複雑な物事を整理する

構造化思考とは、複雑な情報や問題を要素に分け、目的に応じて分類し、階層や関係を整理する考え方です。

「出荷が遅い」という問題だけでは、どこで何が起きているのか分かりません。そこで、まず業務の構成を整理してみます。

```text
物流業務
├─ 入荷
│  ├─ 荷物の受入
│  └─ 入荷時の検品
├─ 在庫管理
│  ├─ 保管
│  └─ 棚卸し
└─ 出荷
   ├─ 仕分け
   ├─ 出荷前の検品
   └─ 積み込み
```

業務を分けることで、出荷の中にも複数の作業があることが見えてきます。さらに、作業の順番や情報の流れを整理すれば、どこを調べればよいのか考えやすくなります。

同じ情報でも、目的によって整理の仕方は変わります。担当部署ごとに分ける場合もあれば、工程や原因の種類ごとに分ける場合もあります。

AIに相談するときも、目的、現在の状況、問題、制約を分けて伝えると、何を考えてほしいのかが明確になります。構造化能力は、情報を考えたり説明したりできる形に整える力です。

### システム思考 ― つながりが生む変化を見る

システム思考とは、構成要素だけでなく、それらの関係や相互作用から、全体で起きる現象を考える方法です。

倉庫の各工程が一時間に処理できる商品数を、次のように仮定します。

| 工程 | 改善前 | 仕分け改善後 |
| --- | --- | --- |
| 仕分け | 80個 | 120個 |
| 検品 | 90個 | 90個 |
| 積み込み | 100個 | 100個 |

この単純な例では、仕分けを120個に増やしても検品の能力が90個のままなら、長期的には一時間に90個を超えて出荷し続けることはできません。検品待ちの商品が増える可能性があります。

また、ある変化の影響が巡って元の要素に戻ることをフィードバックと呼びます。

出荷の遅れ → 問い合わせの増加 → 作業時間の減少 → さらなる出荷の遅れ

このような循環も考慮すると、単に一つの作業を速くするだけでは解決できない問題が見えてきます。実際にどんな関係があるかは観察やデータで確かめます。

構造化思考によって業務の構成を把握し、システム思考によって要素同士の影響や全体の変化を理解できます。両者は重なる部分もあり、互いに補完する考え方です。

## 根拠をもとに判断する力

### 論理的思考 ― 理由と結論をつなぐ

論理的思考とは、前提や理由と結論の関係を整理し、考えが筋道立っているかを確かめることです。

「仕分けが速くなる」から「出荷が速くなる」という結論には、仕分けの後にある工程も十分に処理できる、という前提が隠れています。

例えば、システムが開けないからといって、システムそのものが壊れたとは限りません。同僚のPCでは開けるなら、自分の接続環境などにも原因の候補があります。

結論に至るまでの途中の理由を考えると、考えの飛躍や不足している情報が見えてきます。筋道が通っていても前提が誤っていることはあるため、批判的思考による根拠の確認も必要になります。

### 批判的思考 ― 根拠を確かめる

批判的思考とは、情報や主張の根拠、前提、限界を吟味し、その結論がどの程度妥当かを考えることです。

作業時間が半分になるという説明には、何の作業を、どのような条件で測ったのかという疑問が生まれます。AIの結果を確認したり修正したりする時間も含まれているでしょうか。

| 情報の種類 | 例 |
| --- | --- |
| 観測された結果 | ある試験では60分の作業が30分になった |
| 解釈 | AIが作業の効率化に役立った可能性がある |
| 一般化 | どの仕事でも作業時間が半分になる |

最初の結果が正しくても、最後の主張が正しいとは限りません。事実と解釈を分け、必要に応じて元の資料や測定条件を確かめます。

批判的思考は、何でも否定することではありません。根拠の確かさと判断の重要性に応じて、どこまで信頼できるのかを考えることです。

論理的思考は、理由から結論へ至る筋道を確かめます。批判的思考は、その理由や前提をどこまで信頼できるのかを吟味します。両方の視点があることで、もっともらしい説明をそのまま受け入れず、納得できる判断に近づけます。

## 未知の問題を解き明かす力

### 仮説思考 ― 仮の答えを確かめる

仮説思考とは、答えが確定していない段階で説明や解決策の候補を置き、検証によって更新する考え方です。

出荷が遅い原因について、いくつかの仮説を考えます。

| 仮説 | 確認すること |
| --- | --- |
| 仕分けが遅い | 仕分けの処理数・待ち時間 |
| 検品に時間がかかる | 検品待ちの商品数 |
| 積み込みが滞っている | 積み込み時間や車両の到着状況 |

仮説があると、次に何を調べるかが明確になります。得られた結果が仮説に合わないなら、別の原因を考えます。一致したとしても、それが本当の原因なのかは必要に応じて追加で確かめます。

これは新しいシステムを作る場合にも使われます。AIで棚卸しの作業を短縮できるか、限定した条件で試すPoCも、実現可能性を検証する活動の一つです。

## 三つの力は互いにつながる

| 考える力 | 思考法 | 考えるときの問い |
| --- | --- | --- |
| 整理し、全体を捉える | 構造化思考・システム思考 | 何がどう構成され、全体にどう影響するか |
| 根拠をもとに判断する | 論理的思考・批判的思考 | 理由と結論はつながり、根拠は十分か |
| 未知の問題を解き明かす | 仮説思考 | 何を確かめれば原因や可能性が分かるか |

倉庫の出荷遅延を考える場合も、業務の構造と各工程の関係を捉え、改善案の根拠を確認し、原因や対策について仮説を立てて検証できます。

検証の結果によって新しい関係に気づき、最初の整理や判断を見直すこともあります。決まった順番で使う必要はありません。

AIの提案を読むとき、システムの障害を調べるとき、業務改善を考えるときにも、必要な視点を組み合わせられます。

## 今日のなるほど

冒頭の倉庫では、仕分けの作業だけに目を向けると、出荷全体の問題を見落とす可能性がありました。

**考える力とは、物事を整理して全体を捉え、根拠をもとに判断し、分からないことを確かめながら、より確かな理解へ近づく力です。**
