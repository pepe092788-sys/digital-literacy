データ型、プログラミング言語、サーバー、ネットワーク。

一つずつ調べれば、それぞれが何を意味するかは分かります。

しかし、これらは実際のシステムの中で、どのようにつながっているのでしょうか。

## 知識を集めることと、つなげること

知識の体系化とは、個々の知識を整理し、その関係や全体の中での位置づけを明らかにすることです。

例えば、社員番号を登録する業務システムを考えてみます。

社員番号を数字ではなく文字列として扱うためには、データ型の知識が役立ちます。その情報を処理するためにプログラムがあり、ネットワークを通じてサーバーと情報をやり取りします。

別々に学んだ概念が、一つのシステムの中で役割を持ってつながります。

## 関係の種類を考える

知識には、さまざまな関係があります。

| 関係 | 例 |
| --- | --- |
| 構成 | コンピュータはCPUやメモリなどで構成される |
| 前提 | データ型を知ると、プログラムのデータ処理を理解しやすい |
| 仕組み | ネットワークを通じてサーバーに要求が届く |
| 比較 | 単体テストと結合テストでは確認する範囲が違う |
| 応用 | 仮説を検証する考え方はPoCにもつながる |

分類は知識を探すために役立ちます。一方、関係を考えることは、複数の知識を使って説明するために役立ちます。

## つながりは新しい問いを生む

例えば、データ型とセキュリティは別の分野に見えます。

しかし、入力されたデータをプログラムがどのように扱うのかを考えると、想定外の入力によって何が起こるのかという疑問が生まれます。

異なる分野の関係に気づくことが、新しい学びのきっかけになります。ただし、似ているだけの概念を同じ仕組みと決めつけず、実際にどのような関係があるのかを確かめます。

## 最初から体系が完成している必要はない

学び始めた段階では、まだ関係が見えないこともあります。

新しい知識に出会うたび、既存の理解と照らし合わせ、必要に応じて分類や関係を見直していけばよいのです。

このサイトも、知識の深度と分野による分類に加え、関連記事を通して知識のつながりを示しています。興味のある記事から自由に移動することで、別の知識に出会えます。

## 今日のなるほど

知識は、一つずつ増やすこともできますが、互いにつなげることで新しい意味を持ちます。

**知識の体系化とは、知っていることを、考えるために使える形へ整理することです。**
