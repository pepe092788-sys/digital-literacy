会社のホームページに、新しいお知らせを掲載することになりました。

掲載する文章はすでに完成しています。しかし、WebサイトがHTMLやCSSを直接記述して作られている場合、ページを追加するには、そのファイルを編集する必要があります。

記事を掲載するたびに、Webサイトを作るための技術が必要になるわけです。

文章を書くことと、Webページを作ることは、本来異なる作業のはずです。

この二つの作業を分離し、Webサイトの運営を効率化するために利用されるのがCMSです。

## CMSとは

CMS（Content Management System）とは、文章や画像などのコンテンツを登録・編集・管理するためのシステムです。

日本語では「コンテンツ管理システム」と呼ばれます。

代表的なCMSにはWordPressがあります。ブログや企業のホームページ、ニュースサイトなど、さまざまなWebサイトの構築・運営に利用されています。

CMSを利用すると、一般的には管理画面から文章や画像を登録し、Webサイトに掲載できます。

記事を書く人が、必ずしもHTMLやCSSの知識を持っている必要はありません。

**Webサイトを作ることと、Webサイトを運営することを分離できる。**

これがCMSの大きな利点です。

## WordPressはどのような仕組みなのか

代表的なCMSであるWordPressを例に、その仕組みを見てみましょう。

WordPressでは、主に次の要素を組み合わせてWebサイトを構築します。

| 要素 | 役割 |
| --- | --- |
| コンテンツ | 記事や画像などの掲載内容 |
| テーマ | ページのレイアウトやデザイン |
| プラグイン | お問い合わせフォームなどの追加機能 |
| データベース | 記事や設定などの情報を保存する |
| 管理画面 | コンテンツの登録・編集や設定を行う |

例えば、管理画面から新しい記事を登録すると、記事の内容がデータベースに保存されます。

閲覧者がその記事を開くと、一般的なWordPressの構成では、保存されている記事の情報とテーマを組み合わせてWebページを生成します。

コンテンツとデザインが分離されているため、記事の内容を変更することなく、Webサイト全体のデザインを変更することもできます。

一つひとつのHTMLファイルに文章やデザインを記述する場合と比べると、Webサイトの運営が効率的になります。

## 管理画面と公開サイトは一体になっているのか

ここで、一つ気になることがあります。

Webサイトを閲覧する人には、記事を読む機能があれば十分です。

しかし、一般的なWordPressでは、閲覧者向けの公開サイトと、管理者向けの管理画面が、同じWordPressのシステム上で動作しています。

| 利用者 | 利用する機能 |
| --- | --- |
| 一般の閲覧者 | 記事を閲覧する |
| 記事の作成者 | 記事を登録・編集する |
| サイト管理者 | ユーザーやサイトの設定を管理する |

もちろん、一般の閲覧者が自由に記事を編集できるわけではありません。

認証やアクセス権限によって、利用できる機能が制限されています。

しかし、記事を閲覧するだけのWebサイトを公開するために、記事を編集したり削除したりする機能も、同じシステム上で動作していることになります。

管理機能へのアクセスが適切に制限されていなかったり、プログラムにセキュリティ上の弱点が存在したりすれば、不正に操作される可能性があります。

## 便利になるほど、守るべきものが増える

CMSには、Webサイトを効率的に運営するためのさまざまな機能が備わっています。

例えば、ログイン機能、ファイルのアップロード機能、記事の編集機能、プラグインによる機能拡張などです。

しかし、それぞれの機能は、攻撃者にとっても攻撃対象になり得ます。

セキュリティの分野では、このような攻撃に利用され得る接点や経路の集合を、**アタックサーフェス（攻撃対象領域）**と呼びます。

例えば、HTMLやCSSなどの完成済みファイルを配信するだけの静的なWebサイトと、一般的なWordPressの構成を比較してみましょう。

| 攻撃対象 | 静的サイト | 一般的なWordPress |
| --- | --- | --- |
| Webサーバー | あり | あり |
| 公開サイト上の管理画面 | なし | あり |
| サイトのログイン機能 | なし | あり |
| サーバー側の記事編集処理 | なし | あり |
| サーバー側のデータベース処理 | なし | あり |
| サーバー側で動作するCMSプラグイン | なし | あり |

ここでの静的サイトは、閲覧機能のみを提供する構成を想定しています。

例えば、公開サイトにデータベースへ接続する処理が存在しなければ、その処理の弱点を利用してデータベースに侵入する攻撃は成立しません。

機能を増やすことで利便性は向上しますが、その機能を安全に提供するための管理も必要になります。

## 多くの人が使っていることのメリットとリスク

WordPressのような広く普及したソフトウェアには、もう一つ考慮すべき特徴があります。

例えば、1万個のWebサイトが、それぞれ異なるプログラムで作られているとします。

あるWebサイトに脆弱性が発見されても、ほかのWebサイトに同じ脆弱性が存在するとは限りません。

しかし、1万個のWebサイトが同じCMSやプラグインを使っていたらどうでしょうか。

共通する脆弱性が発見された場合、同じ弱点を持つ多数のWebサイトが攻撃対象になる可能性があります。

攻撃者にとって、一度考えた攻撃方法を複数のサイトに使えることは大きな利点です。

一方で、広く利用されているソフトウェアには、多くの開発者による検証や、脆弱性に対する修正が提供されるというメリットもあります。

自分で開発したシステムでは、自分たちで脆弱性を発見し、修正しなければならない場合もあります。

普及しているから危険とも、普及しているから安全とも、一概にはいえないのです。

CMSを利用する際は、本体やテーマ、プラグインの更新を継続し、不要な機能を削除するなど、適切に運用することが重要です。

## 管理機能と公開機能を分離できないのか

ここまで考えると、CMSの便利な管理機能は利用しながら、公開サイトからは管理機能を取り除くことができないかという疑問が生まれます。

実は、この考え方に沿ったCMSも存在します。

それが**ヘッドレスCMS（Headless CMS）**です。

従来型のCMSは、コンテンツの管理とWebページの生成・表示を担当します。

一方、ヘッドレスCMSは、コンテンツの管理を担当し、Webページの表示は別のシステムに任せます。

| 役割 | 従来型CMS | ヘッドレスCMS |
| --- | --- | --- |
| コンテンツの登録・編集 | CMS | CMS |
| コンテンツの保存 | CMS | CMS |
| Webページの生成・表示 | CMS | 別のシステム |

管理画面から記事を登録する便利さを維持したまま、公開サイトの構成を独立して設計できるわけです。

WordPress自体も、コンテンツの管理だけを担当させるヘッドレスCMSとして利用することができます。

## 完成したページだけを公開する

ヘッドレスCMSと静的サイト生成の仕組みを組み合わせると、例えば次のような構成にすることができます。

1. 管理者がCMSで記事を登録する。
2. Webページを生成するシステムがCMSから記事を取得する。
3. 記事とデザインを組み合わせてHTMLを生成する。
4. 完成したファイルを公開サーバーに配置する。
5. 閲覧者は公開されたページを読む。

この構成では、閲覧者が記事を読むたびにCMSへ接続する必要はありません。

CMSへのアクセスを管理者やページ生成処理に限定すれば、管理機能を一般の閲覧者に直接公開せずに済みます。

ただし、ヘッドレスCMSを導入しただけで、このような安全性が得られるわけではありません。

管理画面やシステム間のデータ取得機能をどのように公開するかによって、安全性は変わります。

また、管理システムが侵害されたり、公開処理が改ざんされたりすれば、不正なコンテンツが公開される可能性もあります。

重要なのは、CMSという製品の種類だけでなく、システム全体をどのように構成するかです。

## CMSを使わないという選択肢

この教材サイトでは、記事をMarkdownという記述形式のファイルで管理し、Astroというツールを使ってWebページを生成しています。

完成したファイルを公開するため、公開サイト上に記事を編集するための管理画面は存在しません。

もちろん、CMSのような管理画面があれば、プログラミングの知識がない人でも記事を編集しやすくなるでしょう。

しかし、AIを利用して記事を作成し、ファイルとして管理する運用であれば、必ずしも専用のCMSを導入する必要はありません。

| 構成 | 適した利用場面 |
| --- | --- |
| 従来型CMS | 管理画面から手軽にWebサイトを運営したい |
| ヘッドレスCMS | コンテンツ管理と公開方法を独立して設計したい |
| CMSを使わない静的サイト | ファイルを中心に記事を管理し、シンプルに公開したい |

どの方法が優れているかは、Webサイトの目的や運営方法によって変わります。

## 守ることと、守る必要をなくすこと

セキュリティ対策というと、複雑なパスワードを設定したり、アクセス制限を厳しくしたりすることを想像するかもしれません。

これらは、存在する機能を安全に利用するための対策です。

しかし、その機能をそもそも公開する必要がないのであれば、公開しないという選択肢もあります。

例えば、図書館に本を読みに来た人が、蔵書の登録や廃棄を行うための事務室に立ち入る必要はありません。

事務室に厳重な鍵をかけることも重要ですが、閲覧者が事務室に近づく必要のない構造にすることも、安全性を高める方法です。

Webサイトの管理機能についても、同じ考え方ができます。

便利な機能を増やすことだけでなく、その機能がどこに必要で、誰が利用するのかを考える。

それもシステムを設計する上で重要な視点です。

:::tip[今日のなるほど]
CMSは、コンテンツの作成・管理と、Webサイトの構築を分離し、情報発信を効率化する仕組みです。

一方、便利な機能が増えれば、安全性を考慮すべき場所も増えます。

管理と公開を分離することで、利便性を維持しながら、公開環境の攻撃対象領域を小さくできる場合があります。

**セキュリティとは、存在する機能を厳重に守ることだけではありません。守る必要のある機能そのものを減らすことも、重要な対策なのです。**
:::
