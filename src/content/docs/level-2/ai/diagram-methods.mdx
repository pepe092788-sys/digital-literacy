作業の遅延を説明したい場合と、申請の手順を説明したい場合では、同じ図を使うとうまく伝わりません。前者は原因候補の関係、後者は処理の順序が重要だからです。

図解手法とは、情報のどの関係を見える形にするかを決める方法です。手書き風か平面的かというデザインの選択とは異なります。

## 代表的な図解手法

| 図解手法 | 表すもの・用途 |
| --- | --- |
| フローチャート | 手順、処理、条件分岐 |
| 特性要因図（魚骨図） | 問題に対する原因候補の分類 |
| マインドマップ | 中心テーマから広がる発想 |
| コンセプトマップ | 概念同士の関係とその意味 |
| ツリー図 | 階層・分類 |
| ピラミッド図 | 階層、段階、優先順位 |
| ベン図 | 集合の共通部分と違い |
| マトリクス図 | 二つ以上の評価軸での整理 |
| タイムライン | 時間順の出来事 |
| サイクル図 | 繰り返しの工程 |
| サンキー図 | 流れと量（線の幅で表す） |
| アーキテクチャ図 | システムの構成要素と接続 |
| シーケンス図 | 複数の要素のやり取りの順序 |
| ジャーニーマップ | 利用者の行動・体験の推移 |
| 分解図 | 部品と組み立ての関係 |
| 断面図 | 外から見えない内部構造 |

## 特性要因図とフローチャートは何が違うか

特性要因図では、結果として現れた問題に対して原因の候補を枝に分けます。原因を整理するための図であり、枝に書かれたものが実際の原因だと証明する図ではありません。

フローチャートは処理がどの順序で進むかを示します。判断によって次の処理が変わる場合は、条件と分岐を記載します。問題の原因候補を洗い出す場面と、作業手順を設計する場面で使い分けられます。

## AIへの依頼例

> 作業遅延の原因候補を設備・人・方法・材料の観点から整理し、特性要因図にしてください。確認済みの原因と未検証の仮説を区別してください。

図解手法を指定した後に「フラットデザインで」「グラレコ風で」などを加えることもできます。矢印の向きや分岐、数値、因果関係は装飾より優先して確認します。

## 今日のなるほど

図は情報を飾るものではなく、関係を伝えるものです。何を明らかにしたいかによって適切な図の形が変わります。
