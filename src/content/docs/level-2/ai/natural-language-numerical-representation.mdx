ChatGPTに日本語で質問すると、日本語で回答が返ってきます。

あまりにも自然なやり取りなので、コンピュータが人間と同じように言葉を扱っているように感じます。

しかし、コンピュータは本来、数値や記号を決められた規則に従って処理する機械です。

では、そもそも人間の言葉をどのようにして計算できるようにしたのでしょうか。

AIの仕組みを理解するために、その出発点までさかのぼってみましょう。

## 文字を数値にする

実は、文字を数値で表現する仕組みは、生成AIが登場するよりもずっと前から存在しています。

それが**文字コード**です。

例えば、Unicodeという国際規格では、文字に次のような番号が割り振られています。

| 文字 | 番号（10進数） |
| --- | ---: |
| A | 65 |
| B | 66 |
| あ | 12354 |
| い | 12356 |
| 猫 | 29483 |
| 犬 | 29356 |

この番号は、文字の意味を数学的に分析して決めたものではありません。

人間が共通の約束として定めたものです。

Unicodeでは文字に番号（コードポイント）を割り振り、UTF-8などの方式によって、それを実際に保存・通信できるバイト列に変換します。

<LanguageNumberDiagrams kind="characters" />

この仕組みがあるからこそ、コンピュータで文章を保存したり、メールを送ったり、Webサイトを表示したりできるのです。

AIもまた、この基本的な仕組みの上に成り立っています。

## 文字を数値にするだけでは足りない

文字コードを使えば、人間の文章を数値の並びとして扱えます。

しかし、言語を処理する際に、必ず一文字ずつ扱わなければならないのでしょうか。

例えば、「東京都」という言葉を考えてみます。

「東」「京」「都」という三つの文字として扱うこともできますが、「東京」や「東京都」を一つの処理単位として扱うこともできます。

頻繁に登場する文字の組み合わせをまとめれば、処理する単位の数を減らせる場合があります。

このように、文章をモデルが扱うための単位に分割する処理を**トークン化**と呼び、その単位を**トークン**と呼びます。

## 文字をまとめるルールは誰が決めるのか

日本語には数多くの単語が存在します。

新しい言葉も次々に生まれます。

それらを人間が一つずつ登録していくのは大変です。

そこで、文章の中にどのような文字の組み合わせが頻繁に登場するのかを、コンピュータに調べさせる方法があります。

代表的な方法が、BPE（Byte Pair Encoding）です。もともとはデータ圧縮のためのアルゴリズムで、後に言語処理にも応用されました。

ここで注目したいのは、コンピュータが東京という都市の存在を知らなくても、この処理ができるということです。

「東」と「京」が何度も隣り合って登場している。

ただそれだけの理由で、新しい処理単位を作ることができます。

言葉の意味を知らなくても、文字の出現傾向を調べることはできるのです。

## トークンにも番号を割り振る

こうして作られた処理単位に、それぞれ識別番号を割り振ります。

| トークン | トークンID |
| --- | ---: |
| 東 | 101 |
| 京 | 102 |
| 都 | 103 |
| 駅 | 104 |
| 東京 | 1001 |
| 東京都 | 1002 |

※番号は説明用の架空の例です。

この対応表と分割ルールがあれば、入力された文章をトークンIDの並びに変換できます。

<LanguageNumberDiagrams kind="ids" />

こうした変換を担当するプログラムを、トークナイザーと呼びます。BPEの場合は、学習で得られた統合ルールを使って新しい文章を分割します。

## まだ言葉の意味は分かっていない

ここまでの仕組みで、文章を数値の並びに変換できるようになりました。

しかし、もう一つ大きな問題が残っています。

例えば、「猫」と「犬」はどちらも動物です。

一方、「猫」と「自動車」は、意味の上では大きく異なります。

文字コードやトークンIDを比較しても、このような関係は分かりません。

番号はあくまで識別するためのものだからです。

**言葉を数値で表現することと、言葉の意味や関係を数値で表現することは、別の問題なのです。**

## 一つの言葉を、複数の数値で表現する

そこで、言語モデルでは一つのトークンを複数の数値の組み合わせで表現します。

この数値の組み合わせをベクトルと呼び、トークンをベクトルに対応させる仕組みを埋め込み（Embedding）と呼びます。

<LanguageNumberDiagrams kind="vectors" />

では、この数値は誰が決めるのでしょうか。

人間がすべての言葉について、その意味を分析して数値を決めているわけではありません。

モデルを一から学習させる場合、これらの数値も一般にランダムな値などから始まり、学習を通じて調整されます。

例えば、文章の続きを正しく予測できるように、モデル内部の数値を少しずつ変えていきます。

こうした学習を通じて、言葉の使われ方や文脈上の関係が数値に反映されていきます。実際の言語モデルでは、埋め込みに加えて、その後の計算でも文脈に応じた表現が作られます。

## 人間の言葉がAIの学習材料になるまで

<LanguageNumberDiagrams kind="flow" />

こうして振り返ってみると、AIの仕組みも、一つひとつの技術の積み重ねによって成り立っていることが分かります。

文字に番号を割り振る。

頻繁に登場する文字の組み合わせを調べる。

処理単位を数値の組み合わせで表現する。

予測の結果に応じて数値を調整する。

それぞれの仕組みを単独で見れば、決して魔法のようなものではありません。

しかし、それらを組み合わせ、大規模な学習を行うことで、人間と自然な言葉でやり取りできる仕組みが生まれました。

## 今日のなるほど

AIが人間の言葉を扱えるようになるための出発点には、文字コードというコンピュータの基本的な技術があります。

最初から言葉の意味を理解させたのではなく、まず言葉を計算可能な形に変換し、その後に学習によって言葉の関係を獲得できる仕組みを作りました。

そして、ここから新しい疑問が生まれます。

**言葉の使われ方を学習することと、言葉の意味を理解することは、果たして同じなのでしょうか。**

AIの仕組みを知ることは、人間にとっての言語や知能とは何かを考えることにもつながります。
